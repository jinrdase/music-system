# 2026-11-02

## 修复：购物车结算无反应 + 缺少模拟支付入口

用户反馈：专辑加入购物车后点击结算没反应，且看不到模拟支付。

根因（排查结论）：
1. 两个前端并存：`frontend/`（Vue3+Element Plus，dev 端口 5173，主前端）和 `src/main/resources/static/`（8080 内置旧页面）。
2. 8080 旧页面的全局点击处理器缺少 `const id = Number(action.dataset.id)`，所有带 data-id 的按钮（加购、结算勾选、支付等）都抛 `ReferenceError: id is not defined`，表现为“点了没反应”。
3. 结算对实物专辑强依赖收货地址，无地址时只有一闪而过的 toast，用户感知为无反应；且购物车页下单后直接跳订单列表，没有任何支付/模拟支付步骤（8080 旧页支付弹窗只有查询/取消，无模拟支付按钮）。
4. 后端本身链路是通的：`pay.mock-enabled=true` 已配置，`/api/payment/mock-pay/{paymentNo}` 正常；`/api/order/createFromCart`（购物车合并结算）后端早已存在但前端从未接入。

改动：
- 新增 `frontend/src/components/PaymentDialog.vue`：统一支付弹窗（创建支付单 → 无 payUrl 时显示「模拟支付」按钮，有 payUrl 时打开支付宝收银台 + 查询状态）。
- 重写 `CartView.vue`：新增「结算所选」批量结算（接入 createFromCart）+ 单件结算；无地址时弹窗引导去添加；下单后直接弹出支付弹窗；单件下单成功后清理购物袋。
- `OrderListView.vue`/`OrderDetailView.vue` 改用 PaymentDialog（此前是静默自动 mock，无任何界面反馈）。
- `api/order.js` 增加 `createFromCart`。
- 后端 `CartItemVO`/`ShoppingCartServiceImpl` 增加 `productType` 字段（前端结算判断是否需要地址用；未重启后端时前端有 albumDetail 兜底）。
- 8080 旧页面 `app.js`：补 `const id` 定义、支付弹窗加「模拟支付」按钮、创建订单后自动弹出支付、无地址时 confirm 引导。已同步 `target/classes/static/`（重启后也会从 src 拷贝）。
- `e2e/store-flow.spec.js` 更新为新流程；顺带修复盲盒奖品图片断言的既有 flaky（奖品可能无图）。

验证：Playwright 实测 5173 全流程（结算→模拟支付→已支付→订单详情）与 8080 全流程均通过；`npx playwright test e2e/store-flow.spec.js` 2 passed / 3 skipped（需管理员环境变量）；`mvn compile` 通过。

遗留/注意：
- 后端 Java 改动需重启 Spring Boot 才生效（前端有兜底，不重启也不影响功能）。
- 测试在 dev 库留下了 qa_admin_local 的测试订单/地址与 e2eqa* 用户。
