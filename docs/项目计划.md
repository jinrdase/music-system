# 潮流音乐专辑及衍生品发售系统项目计划

## 1 项目目标

完成一个可运行、可演示、可验收的音乐专辑及衍生品电商系统。交付范围包括 Vue 前端、Spring Boot 后端、MySQL 数据结构与迁移、用户交易流程、管理员后台、自动化测试和项目文档。实施遵循保留现有业务数据、增量改动、敏感配置不入 Git 的原则。

## 2 工作分解

| 阶段 | 工作内容 | 交付物/验收依据 | 状态说明 |
|---|---|---|---|
| 1 需求与架构 | 梳理用户、管理员、交易及非功能需求 | 需求分析说明书、概要设计说明书 | 本计划和文档基于当前项目形成 |
| 2 后端基础 | Spring Boot 配置、统一响应、JWT、Mapper/Service 分层 | Maven 编译及接口实现 | 历史记录：clean compile 曾通过；答辩前按当前工作区重新验证 |
| 3 用户与目录 | 注册登录、个人信息、专辑/歌曲浏览 | 用户和商品 Controller、前端页面 | 按真实接口清单验收 |
| 4 交易闭环 | 地址、购物车、订单、支付、物流、退款 | 订单状态和数据库记录可追踪 | 模拟支付可用于本地演示；真实支付需外部凭据 |
| 5 盲盒 | 盲盒配置、下单、支付后抽取、保底、抽取记录 | 盲盒服务及相关表 | 结果由后端支付成功链路生成 |
| 6 管理后台 | 商品、歌曲、用户、订单、退款及审计操作 | 管理页面、后端角色校验和审计 | 仅对已存在 API 的操作做功能承诺 |
| 7 前端 | 独立 Vue 页面、路由、Pinia、Axios、响应式样式 | `npm run build`、浏览器测试 | 有既有构建和 Playwright 通过记录；执行最终交付前需复跑 |
| 8 媒体与播放 | 图片上传/展示、歌曲音源和播放器 | 上传接口、媒体 URL、播放器验收 | 图片有专项工作；真实音源当前 0/10 |
| 9 测试 | 单元/集成、接口、权限、并发及 E2E | 测试报告与可重复用例 | 对未实际执行的测试不记录为通过 |
| 10 文档与交付 | 更新接口、运行、数据库、测试和答辩材料 | `docs/` 文档集 | 本计划及配套说明纳入文档交付 |

## 3 建议任务顺序

### P0 交付前阻塞项

1. 确认答辩环境的 MySQL 3307、Redis 6379、JWT_SECRET 和 8080 端口状态。
2. 使用隔离的 QA 用户复核登录、商品浏览、地址、订单及模拟支付。
3. 复核管理员后台关键功能与服务端角色权限；不要修改现有普通用户角色。
4. 确认关键迁移已在目标测试库执行，先备份，再只运行缺少的增量脚本。
5. 将歌曲播放功能如实演示为播放器交互；若要展示真实播放，先补充有授权的音频资源并验收 URL。

### P1 质量完善

1. 补足订单状态转换、支付重复通知、退款事务、库存并发和盲盒保底测试。
2. 对前端核心流程复跑 Playwright，检查 Console、Network 和关键数据变化。
3. 对真实支付宝沙箱进行独立配置验证，不用真实资金或生产商户账户做毕业设计演示。
4. 整理图片、音频等 uploads 持久化部署方式与备份流程。

### P2 后续增强

1. 配置真实授权音源，完成真实音频文件上传与试听体验。
2. 完善多商品合并结算、运营统计等以产品需求确认后的功能。
3. 完成部署环境的 HTTPS、日志保留、备份恢复和监控配置。

## 5 测试及退出标准

- 后端 Maven 编译通过，前端生产构建通过。
- 用户端核心业务流程能通过真实接口完成，订单与支付状态可核验。
- 管理端接口对普通用户拒绝访问；订单、地址等数据具备归属隔离。
- 盲盒支付后生成与抽数相符的抽取记录，重复支付通知不重复抽取。
- 未实际执行或依赖外部凭据的测试明确标注“未测试/受阻”，不能写为通过。
- 数据库不清库、不删除现有账号或业务记录，测试数据可识别。
- 交付文档与当前源码、脚本和验证日期一致。

## 6 风险与应对

| 风险 | 应对 |
|---|---|
| 本地端口已被占用 | 先确认进程身份，未知进程不终止 |
| JWT 或支付配置缺失 | 使用本地环境变量；不提交密钥，不把密钥写进报告 |
| Redis/数据库状态与缓存不一致 | 对照数据库库存与业务流水，使用业务补偿逻辑，不手工清缓存 |
| 真实支付条件不足 | 使用模拟支付完成毕业设计演示，清楚说明非真实交易 |
| 音频素材缺失 | 使用有授权素材后再验收真实播放，不伪造播放成功 |
| 迁移影响已有数据 | 备份、审阅 SQL、只执行必要增量变更 |

## 7 项目运行命令

后端和前端分别在两个 PowerShell 窗口运行，确保本机配置已就绪：

```powershell
cd D:\IntelliJ\music-system
mvn -s "$env:USERPROFILE\.m2\settings.xml" spring-boot:run
```

```powershell
cd D:\IntelliJ\music-system\frontend
npm run dev
```

前端地址为 `http://localhost:5173`。数据库初始化和迁移命令应以实际脚本为准；不要在已存在的业务库上直接重导全量初始化 SQL。

## 8 详细工作包

### WP-01 需求确认与基线

对照当前 Controller、DTO、Service 和前端 API，逐个确认功能范围；确认用户角色、订单状态和外部服务边界；检查现有未提交更改和迁移脚本。输入包括当前源码、接口文档和需求分析说明书。输出为已核对需求清单、真实接口清单及已知限制。验收时每项功能都能追溯至真实接口/代码或被标记为规划项，不把旧版学习平台功能当成本项目功能。

### WP-02 后端基础与身份安全

核对 Java 与 Spring 配置、统一响应、参数校验、JWT 和角色权限；确保秘密不进入 Git；编译验证后再运行验证。交付可编译后端、运行说明和认证权限测试记录。验收条件包括登录返回真实 Token、普通用户无法调用管理员接口、用户资源按身份隔离及日志不暴露密钥。

### WP-03 目录、媒体与前端展示

核对专辑、曲目和盲盒页面的字段映射；检查上传接口、URL 映射和文件持久化；检查响应式布局。交付可由真实 API 驱动的列表、详情和图片展示。图片文件必须真实存在且 URL 可访问，空数据和加载失败应有提示，不能以随机占位商品数据冒充后端响应。

### WP-04 用户购物链路

完成地址、购物车、订单、支付和物流流程；确认地址与商品快照、库存回补和状态迁移。验收时下单由服务端重新校验价格和库存；支付成功只推进一次；发货与确认收货按角色及状态控制。

### WP-05 退款与数字商品

验收退款申请资格、管理员审核、重复申请拦截、库存及支付状态联动；检查数字内容访问权限和访问后退款限制。拒绝审核不得污染订单状态；批准流程应可追踪；外部渠道退款未配置时明确标注受阻。

### WP-06 盲盒业务

验收盲盒配置、库存预留、支付后抽取、保底、抽取记录和重复回调。未支付不得有抽取结果；支付后按订单抽数生成记录；重复通知不重复抽取；库存不足不得产生负数。

### WP-07 管理后台及审计

验收专辑、歌曲、盲盒、用户、订单、退款和审计页面；逐个确认接口能力，禁用没有后端支撑的虚假按钮。交付后台功能矩阵、角色越权测试和审计核验。后端角色校验有效，关键管理操作留痕，编辑失败不假报成功。

### WP-08 测试、文档与演示

运行 Maven 编译、前端构建、Playwright 和真实 API 回归；更新需求、设计、数据库、运行和答辩文档；排演展示流程。报告只写实际执行结果；外部条件缺失项标记受阻；演示不用真实支付和生产数据。

## 12 质量门禁

每次准备演示或交付时，逐项确认：

1. 工作区差异已审阅，未覆盖他人未提交修改。
2. Maven 使用项目要求的用户设置文件，编译成功并保存完整日志。
3. 前端依赖已安装，`npm run build` 成功。
4. 自动化测试确实执行，测试账号和数据均为 QA 数据。
5. 关键 API 用实际请求验证，响应码和业务数据有记录。
6. 数据库仅做只读核验或已获批准的测试数据写入，没有清库/重置操作。
7. 未触发真实支付，密钥和密码未出现在终端截图及报告。
8. 浏览器控制台、网络失败和移动端溢出问题有结论。
9. 未验证功能明确写未测，不以编译成功代替运行验收。
10. 演示前确认服务启动方式、端口占用和退出方案。

## 13 估算与优先级管理

由于测试库状态、外部凭据、音频素材和管理员数据条件可能变化，本计划不虚构固定工时。身份、订单、支付、权限缺陷为高优先级；图片和页面交互为中高优先级；真实音源、生产支付及部署监控属于外部依赖或后续增强。范围变化时先评估数据库迁移、接口兼容、前端影响和测试成本，再决定纳入当前迭代。

## 14 风险登记表

| 编号 | 风险 | 影响 | 预防措施 | 发生后处理 |
|---|---|---|---|---|
| R-01 | 8080 被其他程序占用 | 启动失败或访问错服务 | 启动前确认监听 PID 和命令行 | 不结束未知进程，确认后协调端口 |
| R-02 | IDEA 未加载新环境变量 | JWT 初始化失败 | 更新用户变量后完全重启 IDEA | 用安全本地运行配置，不打印变量值 |
| R-03 | 迁移与当前数据库结构不符 | 数据库对象/业务错误 | 备份并检查迁移历史 | 停止迁移，按目标版本制定补丁 |
| R-04 | Redis 与数据库库存不同步 | 超卖或库存显示异常 | 条件更新、锁和失败补偿测试 | 对照库存流水后受控修复 |
| R-05 | 真实支付条件不足 | 不能验收资金渠道 | 准备模拟支付流程 | 明确模拟边界，不触发真实交易 |
| R-06 | 音源地址无效 | 播放无声或失败 | 上传授权音频并验证 URL | 说明播放器 UI 与真实播放的差异 |
| R-07 | QA 数据污染演示展示 | 展示内容混乱 | 使用唯一 QA 标记和测试库 | 保留数据，不未经批准清理 |
| R-08 | 测试报告过期 | 结果不可信 | 每次交付标明执行日期 | 重新运行并更正结论 |

## 15 发布和回退原则

发布前确认代码版本、数据库迁移版本、媒体目录和环境变量。后端发布前执行构建和集成检查；前端发布前执行生产构建并核对 API 地址。数据库变更先在副本验证，备份后分步执行。应用异常时优先回退应用版本或停用新增功能；数据库回滚不能盲目删除字段或数据，需确认旧版本依赖关系。不得为回滚清空数据库或覆盖用户数据。

## 16 答辩准备计划

1. 提前确认 QA 登录方式、环境变量、端口和数据库服务。
2. 选取标记清晰的 QA 商品、盲盒、用户和订单，避免展示真实个人信息。
3. 按固定顺序演示登录、专辑、地址、订单、模拟支付、后台发货/审核、盲盒结果和审计。
4. 对无音源、未配置支付宝等边界准备简洁准确的解释，不现场尝试不确定的外部支付。
5. 准备数据库关系图、订单状态表和盲盒时序说明，能够解释对应代码职责。
6. 演示前确认页面已加载，不展示开发者工具中的 Token 或密钥。

## 17 计划更新规则

每次迭代结束时更新完成项、未完成项、阻塞原因、测试证据和新发现风险。完成状态必须对应实际文件或测试记录。只完成 UI 而后端接口不存在，应标为部分完成；构建成功但未启动，应注明未做运行验证；使用模拟支付，应明确非真实支付。计划文件本身不替代项目实际实现。

## 19 用户故事与验收条件

| 用户故事 | 验收条件 |
|---|---|
| 作为新用户，我希望注册并登录，以便管理个人交易 | 重复用户名被拒绝；正确登录获得真实 Token；错误密码不能登录 |
| 作为用户，我希望找到专辑并查看曲目 | 列表和详情来自 API；空结果有提示；请求参数符合 Controller |
| 作为用户，我希望购买实物商品 | 地址属于本人；后端复核价格/库存；订单保存快照 |
| 作为用户，我希望完成开发演示付款 | 仅模拟支付；状态可查询；重复请求不重复推进 |
| 作为用户，我希望查看物流并确认收货 | 订单本人可见；发货后才能确认；状态迁移受限 |
| 作为用户，我希望发起退款 | 规则根据数字/实物、访问状态和物流状态判断 |
| 作为盲盒用户，我希望购买后获得可追溯的奖品结果 | 先支付后抽取；结果持久化；抽取数与订单数量对应 |
| 作为管理员，我希望维护目录和处理订单 | 服务端校验角色；写操作出现审计记录 |
| 作为项目维护者，我希望安全升级 schema | 先备份，增量执行，旧业务数据不丢失 |

## 21 E2E 测试计划

### 21.1 浏览器准备

确认 `npm run dev` 或测试专用启动配置可访问，Playwright 浏览器依赖已安装，前后端代理目标正确。测试前检查数据库是否为隔离测试库，不能从“本地 URL”推断它一定不含重要数据。QA 管理员凭据从本地忽略目录通过安全方式注入，不写入测试文件。

### 21.2 关键用户流程

E2E 按“注册或加载专用用户 → 登录 → 浏览目录 → 购物车/地址 → 创建订单 → 模拟支付 → 查看状态 → 退款”组织。盲盒用例单独验证创建待付款订单与支付后抽取；未付款取消路径应确认没有抽取记录。管理流程使用单独管理员账号执行，不使用普通用户角色变更伪造权限。

### 21.3 浏览器检查点

- 页面路由加载后标题、关键区块和错误状态符合预期。
- 所有交互通过可访问名称定位，不依赖脆弱 DOM 层级。
- 网络请求方法、路径、参数和响应符合 Controller 定义。
- 无未处理 Promise、Vue 渲染错误和关键资源 404。
- 关键写操作后重新请求数据验证持久结果。
- 测试结束保留明确标记的 QA 数据，不做共享库清理。

## 22 API 回归测试计划

接口回归用例按 Controller 分组。每个用例至少覆盖：无 Token、普通用户正确调用、普通用户访问他人数据、管理员正确调用、非法参数、业务状态冲突。支付与退款额外覆盖幂等与重复状态；盲盒额外覆盖库存、抽取数和支付触发；上传接口覆盖有效文件与大小/类型拒绝。接口文档中的状态码需要分开记录 HTTP 状态和 Result 业务码。

## 23 自动化测试的数据库隔离

推荐为单元测试、集成测试和浏览器 E2E 分配独立配置。单元测试不连接真实业务库；集成测试使用一次性或专用测试 schema；E2E 可以在 QA 数据库执行，但必须用唯一前缀标记并谨慎保留。测试代码不能把生产配置作为默认 fallback。若需要回滚事务，应确认支付服务、文件上传或 Redis 操作不会因事务回滚而留下外部副作用。

## 24 回归优先级

| 优先级 | 场景 | 回归时机 |
|---|---|---|
| R0 | 登录、JWT、管理员权限、用户归属 | 修改安全或认证代码后每次 |
| R0 | 库存扣减/回补和订单状态 | 修改订单、库存、定时任务后每次 |
| R0 | 支付幂等和盲盒支付后抽取 | 修改支付/盲盒 Service 后每次 |
| R1 | 退款资格及状态联动 | 修改退款规则或支付适配器后 |
| R1 | 上传、图片与音频 URL | 修改媒体配置或页面展示后 |
| R2 | 响应式细节、辅助提示 | CSS/布局改动后 |

## 25 缺陷跟踪规则

每个缺陷应有可复现步骤、预期和实际结果、环境、日志/网络证据、受影响模块和风险等级。优先处理数据错乱、越权、重复扣款/抽奖、库存负值等高风险缺陷。纯视觉差异可安排在功能正确之后。关闭缺陷前需验证原失败用例并执行相邻业务回归；不能只因页面不报错就关闭后端数据缺陷。

## 26 交付版本与变更冻结

答辩前对源码、数据库脚本和文档建立明确版本标识。进入演示冻结期后，仅接受影响演示正确性或安全性的必要修复。任何冻结期变更都应运行对应回归用例并保留日志。不要在提交前进行依赖大升级、数据库重建或大范围格式化。Git 状态应检查但不得擅自清理、覆盖或提交未授权修改。

## 29 演示中断预案

若后端启动失败，保留首条异常并说明检查步骤，不在现场临时清理数据库。若端口被占用，确认 PID 身份后再决定如何处理。若 Redis 不可用，暂停库存相关演示，避免造成测试数据不一致。若支付渠道不可达，切换到已确认开启的本地模拟流程，不输入真实支付信息。若音源 404，展示播放器代码/状态说明，不宣称已经播放成功。若网络异常，截图/报告只可使用以前留存的真实记录并标注执行时间。

## 30 计划完成定义

计划中“完成”的含义是：实现存在、接口与参数已核对、正向和关键反向路径已测试、数据结果可追溯、文档与当前行为一致。若上述部分缺失，使用“部分完成”或“待验证”。计划不要求为了页数或演示观感虚构覆盖率、性能数字和成功结果。

## 31 交付评审流程

交付评审按“代码—运行—接口—业务数据—文档”顺序执行：

1. **代码审阅：** 查看 Git 差异，确认只改计划范围内文件，不覆盖已有业务修改。
2. **构建验证：** 使用指定 Maven settings 编译后端，使用 lockfile 对应依赖构建前端。
3. **启动验证：** 检查端口和依赖服务，再用目标运行配置启动一次，记录日志首个异常。
4. **接口验证：** 对照 Controller 发出真实 HTTP 请求，记录 HTTP 状态与业务码。
5. **数据验证：** 使用只读 SQL 检查 QA 订单、支付、库存、物流、退款和抽取数据。
6. **浏览器验证：** 使用 Playwright 检查用户流程、管理员路由、Console、Network 和窄屏布局。
7. **文档核对：** 将实现限制、执行日期和测试结果同步到报告，不保留过时结论。
8. **风险确认：** 检查数据备份、秘密配置、外部支付和音源授权条件。

评审人应能从报告中的用例编号找到对应运行证据。如果证据不存在，状态应为“待验证”，不能因功能看似完成就标记通过。

## 34 项目风险升级规则

出现以下情况应暂停相关写操作并升级给项目负责人：可能删除或覆盖业务数据；迁移需要重建表或大范围回填；支付/退款可能真实扣款；管理员账号需更改现有用户角色；测试将调用外部短信/支付等有成本服务；当前工作区存在无法解释的用户改动。定位问题期间可继续进行不依赖该操作的只读检查和文档完善。

## 35 开发与测试数据治理

QA 数据命名应稳定可识别，例如使用专用前缀或测试标识；不要在测试里随机生成无法定位的长尾数据。测试开始前记录是否会新增用户、订单、支付单和抽取记录；完成后默认保留并注明清理策略。确需清理时，先生成只匹配 QA 标记的候选记录清单，由授权人员复核后执行，禁止在共用数据库上使用全表删除。

测试账号凭据应保存在 Git 忽略且 ACL 受限的本地文件或秘密管理系统。浏览器测试通过临时环境变量注入，并在测试进程结束后清除。测试脚本不得默认在控制台打印凭据。正式报告只描述“凭据已配置/未配置”。

## 36 质量指标定义

如需向导师报告质量数字，先明确口径：

- **接口覆盖率：** 已实际请求验证的接口数/本轮计划接口数，不按 Controller 方法总数臆算。
- **页面通过率：** 实际打开并验证交互的路由数/本轮页面数，空白或仅静态展示也须分类。
- **自动化通过率：** 本次运行通过用例数/执行用例数，跳过用例单列。
- **缺陷关闭率：** 已复测关闭的问题数/本轮发现问题数。
- **媒体可用率：** 实际 HTTP 可访问且浏览器可显示/播放的资源数/待测资源总数。
- **交易闭环完成率：** 有请求、状态和数据库证据的业务流程数/计划流程数。

所有指标须注明时间、版本和环境，不能将历史 Playwright 记录与本次运行混算。

## 37 数据库迁移执行清单

1. 列出迁移文件及其变更对象。
2. 确认目标库不是生产库或已有授权窗口。
3. 只读检查当前表/字段/索引及历史数据规模。
4. 创建可恢复备份并验证备份文件非空。
5. 在副本执行脚本，核对 SQL 错误和耗时。
6. 对照新旧 schema，确认未意外删除字段或数据。
7. 运行针对新增字段/索引的接口回归。
8. 记录执行人、时间、脚本版本和验证结果。
9. 若失败停止，不继续运行后续依赖迁移。
10. 正式执行后保留监控和回滚/补偿方案。

## 42 完成状态定义

**完成：** 代码已实现，接口已按真实契约联调，主要正反路径通过，数据可核验，文档已更新。  
**部分完成：** 主要页面或后端路径存在，但缺少完整闭环、权限、异常处理或测试证据。  
**待验证：** 实现存在但本轮没有运行测试，或只通过静态阅读。  
**受阻：** 缺少合法凭据、音源、外部服务或环境访问，且不能安全替代。  
**不在当前范围：** 需求尚未确认，不作为缺陷，也不能宣传为已实现。

## 43 总结

本计划的最终目标不是让所有项都显示“通过”，而是使当前实现、测试证据和对外说明一致。项目演示应优先保证核心交易流程稳定，并将模拟支付、无音源、外部商户配置和生产运维能力等边界透明表达。任何可能影响数据库或第三方资金的操作均应先确认范围、权限和回退措施。
