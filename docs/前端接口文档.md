# 前端对接接口文档（全量）

> 面向前端同学的完整接口参考，覆盖系统**当前全部功能**（一期 + 二期 + 支付宝沙箱），每个接口均与后端代码逐一核对。
> 二期各批次的变更历史见《二期接口文档.md》；本文是日常开发的唯一依据，两端不一致时以本文 + 后端代码为准。

## 1. 全局约定

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:8080`（前端 dev 5173，代理到 8080） |
| 认证方式 | 除标注"免登录"外都要带头 `Authorization: Bearer <token>`；token 来自登录接口，24h 有效 |
| 统一返回 | `{code, message, data}`；`code=200` 成功；HTTP 状态码基本恒为 200，**业务成败看 code** |
| 参数校验失败 | `code=400`，message 是第一条校验错误（可直接 toast） |
| 未登录/令牌失效 | `code=401` → 清除本地 token、跳登录页 |
| 无权限 | `code=403`（普通用户调管理接口、操作他人数据） |
| 业务失败 | `code=500` + 可展示的 message（如"库存不足"）；`data=null` |
| 分页请求 | `current`（从 1 开始）+ `size` |
| 分页响应 | `{records: [...], total, size, current, pages}` |
| 时间格式 | `yyyy-MM-dd'T'HH:mm:ss`（如 `2026-10-30T11:20:30`）；**例外**：支付返回的 `expireTime` 是毫秒时间戳（number） |
| 金额 | 元，number，两位小数 |

## 2. 状态与枚举字典（唯一口径）

### 2.1 订单状态 orderInfo.status / statusText

| 值 | statusText | 说明 |
|---|---|---|
| 0 | 待支付 | 15 分钟未支付自动取消（后端定时任务） |
| 1 | 已支付 | 实物/盲盒待发货；数字商品已可取阅 |
| 2 | 已完成 | 买家确认收货 |
| 3 | 已取消 | 手动取消或超时取消 |
| 4 | 已发货 | 管理员已登记物流 |
| 5 | 已退款 | 退款审核通过（终态） |

订单形态 `orderType`：`1`-专辑订单（默认），`2`-盲盒订单。商品形态 `productType`：`PHYSICAL` / `DIGITAL`。

### 2.2 其他字典

| 字段 | 值 | 说明 |
|---|---|---|
| payment.status | 0/1/2/3 | 待支付 / 支付成功 / 支付失败已关闭 / 已退款 |
| refund.status | 0/1/2/3 | 待审核 / 已通过(历史值) / 已拒绝 / 已退款（审核通过的终态是 3） |
| album.status | 0/1 | 下架 / 上架 |
| blind_box.status | 0/1 | 下架 / 上架 |
| sys_user.status | 0/1 | 禁用 / 启用 |
| sys_user.role | user / admin / super_admin | 改角色需 super_admin |
| prizeLevel | 1/2/3/4 | SSR / SR / R / N |
| isLimited、isDefault、isSelected、isGuarantee | 0/1 | 否/是 |

支付渠道已收敛为**仅支付宝**：创建支付只需传 `orderId`，历史参数 `paymentMethod` 已移除（多传会被忽略）。

## 3. 用户模块 `/api/user`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /api/user/register | 免登录 | 注册 |
| POST | /api/user/login | 免登录 | 登录，返回 token |
| GET | /api/user/info | 登录 | 当前用户信息 |
| PUT | /api/user/profile | 登录 | 修改资料 |
| POST | /api/user/avatar | 登录 | 上传头像 |
| PUT | /api/user/password | 登录 | 修改密码 |

### 3.1 POST /api/user/register

| 入参 | 类型 | 必填 | 校验 |
|---|---|---|---|
| username | string | 是 | 4-20 位，仅字母/数字/下划线 |
| password | string | 是 | 6-20 位 |
| confirmPassword | string | 是 | 与 password 一致 |
| nickname | string | 否 | 不填默认同用户名 |
| phone | string | 否 | 11 位手机号，全库唯一 |
| email | string | 否 | 邮箱格式，全库唯一 |

**出参 data**：`UserVO`（注册成功即返回，无需再登录）。

**UserVO 结构**（多处复用）：`{id, username, nickname, phone, email, avatar, status, role, createTime}`。

### 3.2 POST /api/user/login

**入参**：`{username, password}`。**出参 data**：`{token, userInfo: UserVO}`。错误：`用户名或密码错误`、`账号已被禁用，请联系管理员`。

### 3.3 GET /api/user/info

**出参 data**：`UserVO`。

### 3.4 PUT /api/user/profile

**入参 body**（都可选，只传要改的）：

| 字段 | 校验 |
|---|---|
| nickname | 2-20 字符 |
| phone | `1[3-9]` 开头 11 位，全库唯一 |
| email | 邮箱格式，全库唯一 |
| avatar | /media 路径（来自 3.5） |

**出参 data**：最新 `UserVO`。`username` 不可改。错误：`手机号已被其他账号使用`、`邮箱已被其他账号使用`、`昵称长度为2-20个字符`。

### 3.5 POST /api/user/avatar（multipart/form-data）

| form 字段 | 要求 |
|---|---|
| file | 仅 JPG/PNG（**按文件头魔数校验**，改扩展名的假图片会被拒），≤2MB |

**出参 data**：`{"url": "/media/image/avatar-xxx.png"}`——把它作为 3.4 的 `avatar` 保存。图片通过 `http://localhost:8080/media/...` 直接访问。

### 3.6 PUT /api/user/password

**入参**：`{oldPassword, newPassword, confirmPassword}`。

**规则**：旧密码需正确；新密码 **8-20 位且同时含字母和数字**（注意：比注册的 6-20 更严）；不得与旧密码相同；两次输入一致。成功后前端**清 token 跳登录页**。

## 4. 专辑与歌曲 `/api/album`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /api/album/list | 登录 | 在售专辑分页 |
| GET | /api/album/{id} | 登录 | 专辑详情（含歌曲） |
| POST | /api/album/song/{songId}/play | 登录 | 试听计数 +1 |

### 4.1 GET /api/album/list?current=1&size=10&keyword=

只返回**上架**专辑；keyword 对名称/艺人模糊搜索；按发行日期倒序。

**出参 records 元素 `AlbumVO`**：`{id, title, artist, coverUrl, description, productType, releaseDate, price, stock, sales, status, isLimited}`（不含数字内容地址）。

**出参 data**：`AlbumVO` 全部字段 + `songs: SongVO[]`（按曲序升序）。

**SongVO**：`{id, albumId, title, artist, duration, previewUrl, previewDuration, trackNumber, playCount}`。

**错误**：`专辑不存在`。

### 4.3 POST /api/album/song/{songId}/play

无入参；播放页每次试听调一次即可。

## 6. 购物车 `/api/cart`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/cart/add | 加购（同商品自动合并数量） |
| GET | /api/cart/list | 汇总（含每个商品的有效性/现价/库存） |
| PUT | /api/cart/updateQuantity/{cartId}?quantity=3 | 改数量（query 参数） |
| DELETE | /api/cart/remove/{cartId} | 删单条 |
| DELETE | /api/cart/batchRemove | 批量删，**body 是 id 数组** `[1,2,3]` |
| DELETE | /api/cart/clear | 清空 |
| DELETE | /api/cart/clearInvalid | 清理失效商品 |
| PUT | /api/cart/toggleSelect/{cartId}?isSelected=1 | 单条勾选（query 参数） |
| PUT | /api/cart/toggleSelectAll?isSelected=1 | 全选/全不选 |

**加购规则**：同商品合并数量（单商品限购 10 件、购物车上限 50 条）；校验在售与库存。

**GET /api/cart/list 出参 data（CartSummaryVO）**：

```json
{
  "items": [CartItemVO],
  "totalCount": 3,        // 商品条数
  "selectedCount": 2,     // 已勾选条数（仅有效商品计入）
  "selectedAmount": 590,  // 已勾选金额合计（用现价计算）
  "totalAmount": 870
}
```

**CartItemVO**：`{id, albumId, albumName, albumCover, price, quantity, subtotal, isSelected, stock, isValid, createTime}`。
**重要**：`price` 返回的是专辑**当前价**（防改价），`isValid=0` 表示已下架/删除（不可结算，展示快照价）。

## 7. 订单模块 `/api/order`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /api/order/create | 登录 | 单商品直购（生成单明细订单） |
| POST | /api/order/createFromCart | 登录 | 购物车合并结算（多明细订单） |
| POST | /api/order/cancel/{orderNo} | 登录 | 取消待支付订单（实物/数字/盲盒统一） |
| GET | /api/order/my | 登录 | 我的订单分页 |
| GET | /api/order/{orderNo} | 登录 | 订单详情（含物流；含 items） |
| GET | /api/order/{orderNo}/items | 登录（管理员也可） | 订单明细列表 |
| GET | /api/order/{orderNo}/digital-content/{itemId} | 登录 | 明细级数字内容取阅 |
| GET | /api/order/{orderNo}/digital-content | 登录 | 旧版订单级取阅（兼容保留，新页面勿用） |
| POST | /api/order/confirmReceipt/{orderNo} | 登录 | 确认收货 |
| PUT | /api/order/ship/{orderNo} | admin | 发货 |

### 7.1 POST /api/order/create（直购）

| 入参 | 类型 | 必填 | 说明 |
|---|---|---|---|
| albumId | number | 是 | 专辑 id |
| quantity | number | 是 | ≥1 |
| addressId | number | 条件 | 实物必填（本人地址）；**数字商品不传**（传了报错） |
| remark | string | 否 | 备注 |

**行为**：两层防超卖扣库存；订单 15 分钟支付时效（`expireTime`）；返回 `OrderVO`（status=0）。

### 7.2 POST /api/order/createFromCart（购物车结算）

对购物车**已勾选**商品整单结算。**整单拒绝**：任一商品失效/缺货则全部失败。

| 入参 | 类型 | 必填 | 说明 |
|---|---|---|---|
| addressId | number | 条件 | 含实物明细必填；全部数字明细**不传** |
| remark | string | 否 | |

成功后对应购物车项自动删除；总额按专辑**当前价**计算。常见错误：`请先勾选要结算的商品`、`商品「xx」已失效，请清理后再结算`、`商品「xx」库存不足，剩余 N 件`、`结算包含实物商品，必须选择收货地址`、`数字商品无需填写收货地址`。

### 7.3 OrderVO 结构（列表/详情/下单返回通用）

```json
{
  "id": 8, "orderNo": "ORD179...", "userId": 3,
  "albumId": 379730914, "albumTitle": "...", "albumCover": "...",
  "productType": "PHYSICAL", "orderType": 1,
  "receiverName": "...", "receiverPhone": "...", "receiverProvince": "...",
  "receiverCity": "...", "receiverDistrict": "...", "receiverAddress": "...",
  "quantity": 1, "price": 30.00, "totalAmount": 870.00,
  "status": 0, "statusText": "待支付",
  "payTime": null, "cancelTime": null, "expireTime": "...",
  "carrier": null, "trackingNo": null, "shippedAt": null,
  "remark": null, "createTime": "...",
  "items": [OrderItemVO]      // 详情接口与 7.5 明细接口返回；列表接口为 null
}
```

多明细（购物车）订单的 `albumTitle/price/quantity` 是首件快照，仅供列表摘要；真实明细看 `items`。
盲盒订单：`orderType=2`，`drawSummary` 字段在支付后返回抽取结果摘要（如 `SSR·手办、SR·立牌、…`）。

**OrderItemVO**：`{id, orderId, orderNo, albumId, albumTitle, albumCover, price, quantity, subtotal, productType, productTypeText, digitalContentAccessedAt}`。
历史单商品订单无明细记录，`items` 会合成一条返回（id 为 null），前端统一按明细渲染即可。

### 7.4 GET /api/order/my?current=1&size=10

当前用户订单，按创建时间倒序。订单详情 `GET /api/order/{orderNo}` 额外附带物流（已发货/已完成时）和 `items`。

### 7.5 数字内容取阅

**`GET /api/order/{orderNo}/digital-content/{itemId}`**（itemId 来自 7.5 的明细列表，选 `productType=DIGITAL` 的明细）：

- 前置：订单已支付（status 1/2）、明细为数字形态。
- 返回 `data`：内容地址字符串；**首次取阅时间记录在该明细上**（同一订单每件数字商品独立留痕）。
- **退款联动**：任一数字明细取阅后，整单不能再申请退款（见 §9），前端取阅后可隐藏退款按钮。

### 7.6 取消 / 确认收货 / 发货

- 取消：仅待支付(0)可取消，成功后库存自动回补；错误 `只能取消待支付订单`。
- 确认收货：仅已发货(4)；有处理中的退款申请会被拒（`退款申请处理完成前不能确认收货`）。
- 发货（admin）：body `{carrier, trackingNo}`，仅已支付(1)可发货。

## 8. 支付模块 `/api/payment`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /api/payment/create | 登录 | 创建支付，返回沙箱收银台地址 |
| GET | /api/payment/query/{paymentNo} | 登录 | 查询支付结果（**轮询这个**） |
| POST | /api/payment/mock-pay/{paymentNo} | 登录 | 模拟支付（开发环境，免沙箱付款） |
| POST | /api/payment/cancel/{paymentNo} | 登录 | 取消支付 |
| POST | /api/payment/notify/alipay | 免登录 | 支付宝异步回调（**前端不调**） |

### 8.1 POST /api/payment/create

**入参**：`{"orderId": 21}`（渠道固定支付宝，无需传支付方式）。

**出参 data（PaymentVO）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| paymentNo | string | 支付单号（轮询/模拟支付用它） |
| orderNo | string | 订单号 |
| amount | number | 金额 |
| payUrl | string | **支付宝收银台地址**（带签名，约 850 字符）——`window.open(payUrl)` 打开，用沙箱买家账号登录付款 |
| expireTime | number | 过期毫秒时间戳（15 分钟） |

15 分钟内重复调用返回同一支付单（并重新生成收银台地址）。

### 8.2 GET /api/payment/query/{paymentNo}（支付结果轮询）

**出参 data（PaymentResultVO）**：`{paymentNo, orderNo, amount, status, transactionId, payTime}`。

**轮询姿势**：打开收银台后每 2~3 秒调一次；status 变 1 即支付成功。后端内置**查单补偿**——买家在支付宝侧付完后，下一次轮询会自动向支付宝确认并推进订单，**前端无需任何额外处理**。

### 8.3 模拟支付 POST /api/payment/mock-pay/{paymentNo}

演示环境专用：不打开支付宝，直接把待支付支付单推进为已支付（盲盒订单同样会触发抽取）。错误：`模拟支付未开启`、`该支付单当前状态不可支付`、`无权操作该支付`。

## 9. 退款模块 `/api/refund`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /api/refund/apply | 登录 | 申请退款 |
| GET | /api/refund/my | 登录 | 我的退款申请分页 |
| GET | /api/refund/admin/pending | admin | 待审核列表 |
| PUT | /api/refund/admin/{applicationId}/review | admin | 审核（通过即自动执行退款） |

### 9.1 POST /api/refund/apply

**可退条件**：实物订单已支付(1)/已发货(4)；数字订单已支付且**从未取阅**（订单级或任一明细取阅过都拒）。已发货实物必须填退货物流。

| 入参 | 类型 | 必填 | 说明 |
|---|---|---|---|
| orderId | number | 是 | |
| reason | string | 是 | ≤100 字符 |
| description | string | 否 | ≤500 |
| images | string[] | 否 | 凭证图 URL，≤9 张 |
| returnCarrier / returnTrackingNo | string | 条件 | 已发货实物必填 |

**出参 data**：`RefundApplicationVO{..., status: 0}`。常见错误：`只有已支付且未确认收货的订单可以申请退款`、`数字内容已交付，不能在线提交退款申请`（订单中任一数字明细取阅后整单拒退）、`该订单已有待处理或已通过的退款申请`、`已发货订单申请退款时必须填写退货物流公司和物流单号`。

### 9.2 审核（管理员）

`PUT /api/refund/admin/{applicationId}/review`，body `{approved: true|false, auditRemark?}`。

- **通过**：同事务自动执行——申请 → 3 已退款、订单 → 5、支付单 → 3、库存回补；真实支付宝支付还会调用支付宝退款接口（失败则整体回滚，申请仍待审核）。
- **拒绝**：仅申请 → 2，用户可重新申请。
- 并发审核同一申请：后到的返回 `该申请已被处理，请刷新列表`。

## 10. 盲盒模块 `/api/blind-box`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /api/blind-box/list | 登录 | 在售盲盒分页 |
| GET | /api/blind-box/{boxId} | 登录 | 详情（含奖品池与概率） |
| POST | /api/blind-box/order | 登录 | 购买盲盒（生成待支付订单） |
| GET | /api/blind-box/my/records | 登录 | 我的抽取记录分页 |

### 10.1 列表/详情

**BlindBoxVO**：`{id, name, albumId, description, price(String！单抽价), remainCount, status}`。
**详情 data**：`{blindBox: BlindBoxVO, prizes: [{id, boxId, prizeName, prizeLevel, probability, imageUrl, description, createTime}]}`（prizeLevel：1=SSR 2=SR 3=R 4=N；probability 为基础权重，十连抽有 SR/SSR 双保底）。

### 10.2 POST /api/blind-box/order（购买）

| 入参 | 类型 | 必填 | 说明 |
|---|---|---|---|
| boxId | number | 是 | |
| drawCount | number | 是 | 只能 **1 或 10** |
| addressId | number | 是 | 奖品为实物，必须选地址 |
| remark | string | 否 | |

**流程**：下单即预留库存（15 分钟不付款自动取消并回补）→ 返回 `OrderVO`（orderType=2）→ 走 §8 标准支付 → **支付成功后系统自动抽取**，`OrderVO.drawSummary` 变为结果摘要；逐抽明细在 10.3。错误：`抽取次数只能是1次或10次`、`盲盒库存不足`、`购买盲盒必须选择收货地址`。

### 10.3 GET /api/blind-box/my/records?current=1&size=10

**records 元素（抽取记录）**：`{id, userId, boxId, prizeId, prizeName, prizeLevel, probabilityAtDraw, drawCount, isGuarantee, createTime}`（`isGuarantee=1` 表示保底触发；`probabilityAtDraw` 为抽取时刻的概率快照）。

### 11.4 盲盒管理 `/api/admin/blind-boxes`

## 12. 典型业务时序（前端处理要点）

**① 购买专辑**：`album/list` → 加购或直购 `order/create` → `payment/create` → `window.open(payUrl)`（或开发环境 mock-pay）→ 轮询 `payment/query` 至 status=1 → 订单详情确认；数字商品此时可取阅。

**② 购物车结算**：`cart/list` 勾选 → `order/createFromCart` → 同①支付。失败时提示 message 并刷新购物车（整单拒绝，购物车未动）。

**③ 盲盒**：`blind-box/{id}` 看奖品池 → `blind-box/order`（选 1 或 10 连）→ 支付 → 轮询订单详情直到 `drawSummary` 非空 → 展示结果 + `blind-box/my/records` 明细。

**④ 退款**：订单详情判断可退（实物 1/4；数字 1 且明细均未取阅）→ `refund/apply` → 等管理员审核 → `refund/my` 看结果（status 3=已退款，2=已拒绝可重新申请）。

**⑤ 超时关单**：待支付订单 15 分钟后由后端自动取消，前端轮询订单列表即可看到状态变 3，无需倒计时后调取消（当然用户主动取消随时可以）。
