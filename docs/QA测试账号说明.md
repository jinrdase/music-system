# 本地 QA 测试账号说明

本说明不包含任何密码或 Token。

## 普通 QA 用户

Playwright 的端到端流程会自动生成以 `e2eqa` 开头的用户名，使用独立测试账号执行注册、登录、浏览、购物车、地址、下单、模拟支付和退款申请。业务记录保留在数据库中，不会自动删除。

之前人工 API 验收创建的用户名以 `qa` 开头，也会保留在本地数据库。不要在生产数据库运行测试。

## 管理员 QA 账号

本地开发数据库已按用户批准创建独立用户名 `qa_admin_local`，角色为 `admin`。只新增该用户，没有修改任何既有用户角色。SQL 模板保留在 `sql/20261101_local_qa_admin_template.sql` 供复核。

目前登录服务使用项目现有的 `MD5(密码 + music_system_salt_2026)` 算法。该算法是遗留实现，仅用于兼容当前项目，不适用于生产口令存储；正式发布前应设计密码迁移并改用带随机盐的慢哈希算法。

管理员密码由安全随机生成器创建，保存在 Git 忽略的本地文件 `local-test-credentials/qa-admin.txt`；该文件 ACL 已收紧为仅当前 Windows 用户、SYSTEM 和本机管理员可访问，且不会提交到 Git。请在本机查看该文件获取临时测试密码，不要把密码复制进源码、SQL、文档、命令历史或聊天记录。Playwright 通过临时进程环境变量 `E2E_ADMIN_USERNAME`、`E2E_ADMIN_PASSWORD` 读取，测试后清除变量。

## 权限边界

- QA 管理员为独立新增账号；不应把任何现有用户改成管理员。
- 后端管理员接口角色检查仍然生效；前端隐藏按钮不作为权限控制。
- 当前 QA 管理员已通过登录、后台接口和管理员路由浏览器测试。
