## 2026-11-02 歌曲播放链路专项验收（最新）

### 根因与修复

- 专辑详情原来只在 `previewUrl` 非空时显示浏览器原生 `<audio>` 控件，没有显式的歌曲播放按钮、共享播放器状态或加载失败反馈。没有试听地址的曲目因此完全没有播放入口；存在地址的 5 首曲目使用的是 `example.com` 示例链接，浏览器无法获得音频。
- 后端保留的旧静态页也曾只显示原生控件，并在 `play` 事件时增加播放次数；现在状态文字会显示加载/播放/暂停/失败，且只在 Audio 发出真实 `playing` 事件后计数。
- 新增 Pinia 播放状态和全局播放器，加入歌曲行的“播放试听”按钮。播放器支持播放/暂停/继续、上一首/下一首、进度、音量、歌曲名/艺人/专辑封面展示、媒体加载错误和浏览器自动播放限制提示。示例域名被明确识别为无效地址；缺地址或示例地址时显示说明，不发起假播放，也不增加播放次数。
- 播放只使用公开 VO 中的 `previewUrl`。`SongVO` 不对普通用户公开 `audioUrl` 正式音源字段，避免绕过数字内容的业务权限。

### 音频数据核对

- 数据库有 **10 首**未删除歌曲：5 首的 `audio_url` 和 `preview_url` 都是 `example.com` 示例地址；另外 5 首两个字段均为空。
- 对一个示例试听 URL 发出的只读 HTTP HEAD 返回 **404**。项目 `uploads/`、`src/main/resources/static/` 中没有 MP3、WAV、OGG 或 M4A 文件；因此当前真实可播放歌曲数量为 **0/10**。
- 后端专辑详情 `GET /api/album/{id}` 返回歌曲 `previewUrl`，播放次数接口为 `POST /api/album/song/{songId}/play`。前端只在实际媒体开始播放后调用播放次数接口。

### 回归结果

- `npm run build`：成功（Vite 6.4.4，1568 个模块转换）。
- `npm run test:e2e -- e2e/audio-player.spec.js`：**1 passed**。Playwright 登录现有 QA 用户，打开专辑详情、点击播放、检查播放器状态和音频元素；验证示例地址/空地址都明确失败且不报告播放成功、不增加播放次数，同时检查上一首/下一首显示切换、音量值和浏览器 Console/API 错误。
- 与商品图片专项用例合并回归：**2 passed，1 skipped**（后台图片表用例因本地管理员凭据文件不可用而跳过）。
- 由于当前没有任何真实音频文件，浏览器没有可加载成功的 Audio source；实际播放、暂停、继续、进度拖动及媒体元数据加载不能诚实地标为通过。播放器逻辑已接好，需给歌曲上传有使用权的试听音源并保存 `previewUrl` 后才能完成这部分验收。

### 修改文件

- `frontend/src/views/album/AlbumDetailView.vue`：给每首曲目增加明确的播放试听按钮和无音源提示。
- `frontend/src/stores/player.js`：增加播放器队列、来源校验、播放状态、上一首/下一首、进度和音量逻辑。
- `frontend/src/components/GlobalAudioPlayer.vue`、`frontend/src/App.vue`：挂载全局播放器并处理 HTML Audio 事件、封面、歌曲信息、错误及播放次数。
- `frontend/e2e/audio-player.spec.js`：增加无效/缺失音源的浏览器回归用例。
