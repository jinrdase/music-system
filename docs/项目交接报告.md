## 2. 已有业务模块与接口

除注册、登录、测试接口和支付平台通知回调外，`WebConfig` 会拦截 `/api/**` 并要求 JWT。后台接口还会检查管理员角色。实际权限以 JWT 中的用户身份和角色为准。

| 模块 | 已有接口 | 说明 |
|---|---|---|
| 用户 | `POST /api/user/register`、`POST /api/user/login`、`GET /api/user/info` | 注册和登录免 JWT；用户信息需要 JWT。 |
| 健康检查 | `GET /api/test/hello` | 免 JWT，可用于确认应用 HTTP 响应。 |
| 专辑 | `GET /api/album/list`、`GET /api/album/{id}`、`POST /api/album/song/{songId}/play` | 专辑列表、详情和播放计数。按当前拦截配置，均需 JWT。 |
| 购物车 | `POST /api/cart/add`、`PUT /api/cart/updateQuantity/{cartId}`、`DELETE /api/cart/remove/{cartId}`、`DELETE /api/cart/batchRemove`、`DELETE /api/cart/clear`、`PUT /api/cart/toggleSelect/{cartId}`、`PUT /api/cart/toggleSelectAll`、`GET /api/cart/list`、`DELETE /api/cart/clearInvalid` | 需要 JWT；修改类接口会改变购物车数据。 |
| 收货地址 | `POST /api/address/add`、`PUT /api/address/update/{addressId}`、`DELETE /api/address/delete/{addressId}`、`PUT /api/address/setDefault/{addressId}`、`GET /api/address/list`、`GET /api/address/detail/{addressId}`、`GET /api/address/default` | 需要 JWT；下单会记录收货地址快照。 |
| 订单 | `POST /api/order/create`、`POST /api/order/cancel/{orderNo}`、`PUT /api/order/ship/{orderNo}`、`POST /api/order/confirmReceipt/{orderNo}`、`GET /api/order/my`、`GET /api/order/{orderNo}`、`GET /api/order/{orderNo}/digital-content` | 需要 JWT。创建、取消、发货、确认收货会改变订单或库存状态；发货属于后台操作。数字内容接口应验证订单归属和支付状态。 |
| 支付 | `POST /api/payment/create`、`GET /api/payment/query/{paymentNo}`、`POST /api/payment/cancel/{paymentNo}`、`POST /api/payment/notify/wechat`、`POST /api/payment/notify/alipay` | 创建和取消会改变支付/订单状态。通知回调免 JWT；联调前需确认渠道验签、幂等和真实商户配置。 |
| 退款 | `POST /api/refund/apply`、`GET /api/refund/my`、`GET /api/refund/admin/pending`、`PUT /api/refund/admin/{applicationId}/review` | 需要 JWT；审核接口需管理员权限。退款规则区分实物与数字商品。 |
| 盲盒 | `GET /api/blind-box/list`、`GET /api/blind-box/{boxId}`、`GET /api/blind-box/my/records` | 用户可查询盲盒和抽取记录。**业务 Service 有抽取实现，但当前 Controller 没有公开抽取 HTTP 路由**，因此抽取闭环不能从 HTTP API 使用。 |
| 后台专辑 | `GET /api/admin/albums`、`POST /api/admin/albums`、`PUT /api/admin/albums/{albumId}`、`PUT /api/admin/albums/{albumId}/status` | 需要管理员角色。 |
| 后台歌曲 | `GET /api/admin/songs`、`POST /api/admin/songs`、`PUT /api/admin/songs/{songId}` | 需要管理员角色。 |
| 后台盲盒 | `GET /api/admin/blind-boxes`、`POST /api/admin/blind-boxes`、`PUT /api/admin/blind-boxes/{boxId}/status`、`POST /api/admin/blind-boxes/{boxId}/prizes`、`PUT /api/admin/blind-boxes/{boxId}/prizes/{prizeId}` | 需要管理员角色；还没有面向用户的抽取路由。 |
| 后台用户 | `GET /api/admin/users`、`PUT /api/admin/users/{userId}/status`、`PUT /api/admin/users/{userId}/role` | 可管理账号状态和角色；应补充超级管理员授权、越权和审计测试。 |
| 后台审计 | `GET /api/admin/audit-logs` | 查询管理操作审计记录。写操作由拦截器尝试记录；数据库写失败时只记录服务日志。 |
| 媒体上传 | `POST /api/admin/media/image`、`POST /api/admin/media/audio` | 需要管理员角色；本地文件目录默认在用户目录下的 `music-system-uploads`，并通过 `/media/**` 映射读取。 |

## 3. 已完成的主要业务支撑

- 购物车常用增删改、选中和汇总接口，以及下单 DTO 中的地址选择。
- 订单保存商品形态和收货地址快照；实物商品物流信息、发货与确认收货流程已有后端代码。
- 商品区分实物与数字内容；数字内容由已支付订单授权访问。
- 退款申请、后台审核、退货物流字段和实物/数字商品退款规则已有后端代码。
- 后台专辑、歌曲、盲盒、用户状态/角色管理、审计查询和媒体上传接口已有后端实现。
- 盲盒抽取的 Service 层包含扣减库存、记录抽取概率等逻辑，但尚未开放用户 HTTP 抽取接口；不应把该模块描述为完整上线闭环。

## 5. 建议的验证顺序

### 5.1 不依赖数据库写入的基础检查

在项目根目录运行：

```powershell
mvn -s "$env:USERPROFILE\.m2\settings.xml" clean test
```

当前测试覆盖：商品形态判断、退款规则判断、图片/音频文件签名校验，共 5 个测试。当前通过结果不代表支付或数据库集成通过。

启动前确认当前 PowerShell/IDEA 启动进程能读取所需配置；报告和日志不要打印密钥。前端从同源 `/api` 调用后端，无需额外配置 CORS：

```powershell
mvn -s "$env:USERPROFILE\.m2\settings.xml" spring-boot:run
```

确认 MySQL `localhost:3307/music_system`、Redis `localhost:6379` 与本机实际环境一致；端口若不同，以本机服务配置为准。应用运行成功后可先调用不写数据库的健康接口：

```powershell
Invoke-RestMethod http://localhost:8080/api/test/hello
```

再使用已登录用户的 JWT 验证只读接口，例如 `GET /api/album/list`、`GET /api/address/list`、`GET /api/order/my`。由于项目当前 JWT 拦截范围包含这些 API，调用时需在请求头提供 `Authorization: Bearer <本机测试令牌>`；不要把令牌粘贴进报告、终端截图或提交到 Git。

浏览器打开 `http://localhost:8080/`，按“注册 → 登录 → 浏览专辑 → 添加地址 → 创建订单 → 我的订单”验证前端基本流程。支付页会明确提示当前微信/支付宝地址是后端模拟值，不能用于真实付款。管理员页面需用具备 `admin` 或 `super_admin` 角色的账号登录；UI 隐藏按钮不代替服务端授权校验。

### 5.2 需要数据库迁移的业务验收

迁移脚本经同伴审查、备份并应用到专用测试库后，再按以下顺序验证：

1. 管理员创建/上架专辑，分别验证 PHYSICAL 与 DIGITAL 商品信息。
2. 用户添加地址、加入购物车、从勾选商品创建订单，核对订单中的地址快照和商品形态。
3. 通过支付沙箱完成订单支付，确认支付回调重复投递不会重复推进状态。
4. 实物订单测试发货信息、物流查询/确认收货与退款申请；数字订单测试未支付不可取内容、非订单所有者不可取内容、已支付所有者可取内容。
5. 测试退款审批通过/拒绝、已发货实物退货物流信息和数字内容访问后的退款限制。
6. 后续盲盒抽取接口开放并完成安全评审后，再测试并发库存、概率记录、重复请求和支付/退款一致性。当前没有抽取 HTTP 路由，不应将 Service 方法直接暴露到生产环境。

上述会改变数据库状态或触发支付/退款的测试，只能在专用测试库和支付沙箱执行；不要在生产数据上试跑。
